# Discovery breadth

Shared survey for the discovery-only agent and recovery inventory. Establish
scope through the [shared policy](documentation-policy.md). Use the repository's
signals, not a technology checklist or a page-per-directory rule.

## Authority and access

Record the actual repository root and source snapshot, available search/read
tools, audiences, existing instructions, canonical entry points and allowed
dependency sources. Inventory documentation before proposing replacements:

| Field | Purpose |
| --- | --- |
| Path and audience | Distinguish maintainer, consumer, operational and user material. |
| Owner or unknown | Separate review routing from an approved contract owner. |
| Evidence/authority label | Preserve approved intent; distinguish observations, history, proposals and gaps. |
| Source or capability scope | State what the document actually covers. |
| Contradiction or missing material | Identify an owner decision or investigation task. |

Include scattered READMEs, schemas, embedded help, examples, tests, configuration
and existing contribution/CI documentation rules. Legal/security documents and
runtime assets are not disposable documentation. An old date alone does not
justify deletion or rewriting a contract.

**Exit:** existing homes, competing authority, inaccessible evidence and
instruction constraints are recorded. Maintainers and external consumers have
explicit reader tasks or a scoped exclusion.

## Breadth before depth

Inspect tracked-path inventory, package/build/dependency metadata, runtime entry
points, module declarations, registries, routes, events/jobs, persistence schemas
and representative test entry points where present. Prefer available semantic
or symbol tools; follow configuration and registrations when direct calls are
insufficient. An unavailable surface is an explicit limit, not an empty result.

Cross-check product/runtime responsibilities, interfaces/consumers, state/effects
and operation/dependencies. These are complementary evidence views, not four
required agents. Include canonical authority as well as implementation. Connect
entry points to handlers, effects and result consumers. Record source anchors;
mark unexamined responsibilities unknown.

Record surfaces actually inspected and not inspected. Trace generated-code
inputs when available, distinguishing outputs from their authority. Keep
framework behavior outside the checkout as an explicit dependency gap unless
reading that dependency is separately authorized. Negative searches state paths,
query and limits; they do not prove universal absence.

Carry discovered data inputs, stores, outputs and their actual consumers into
the [map-review data-route reconciliation](discovery-map-review.md). Missing
search requires a declared substitute method and limits, not an absence claim.

**Exit:** every candidate exposed by the inspected surfaces has an evidenced
disposition: mapped/grouped responsibility, selected question, deferred
investigation, explicit gap or reasoned exclusion. Keep unassessed surfaces
visible. This is neither a complete dependency graph nor a semantic certificate.
Return to the invoking procedure: discovery-only stops with a map; recovery
continues to separately approved question selection.
